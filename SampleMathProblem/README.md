## 一、为什么用 PhotoSelect 做模板

`PhotoSelect` 是官方的「左右图片二选一 + 摇头选择」示例，和我们要做的口算题**交互完全同构**，区别只在选项内容是图片还是算式。

直接复用的部分：

| 资产 | 价值 |
| ---- | ---- |
| 摇头判定链路 | 参数已调好，含角度环绕处理（见第二章） |
| UI 结构 | 题目 / 左右选项（含选中态、底色）/ 爱心 / 提示 / 扩散 |
| 动效 | `Transit by Time` ×15，0.1~0.5 秒的节奏 |
| 蓝图节点库 | 28 个节点模板，含循环、条件、数组、数学运算 |

> `PhotoSelect` 与 `PhotoSelect2` 的**蓝图完全相同**（135 节点 / 183 连线，节点构成一致），差别只在素材。本工程基于 `PhotoSelect`。

## 二、摇头判定机制

### 2.1 数据链路

```
Get Component Property.Value (Vector3f)   ← 读「3D 跟踪头模」的 Transform 旋转
        ↓
      Peek.Data
        ↓
     Split.Z (Double)                     ← 取 Z 分量（不是 Y）
        ↓
  Greater or Equal ─┐
                    ├→ And → If.Condition
  Less or Equal   ──┘
        ↑
     Update.Next（每帧驱动）
```

### 2.2 ⚠️ 角度是 0~360 度制

这是最容易踩的坑：**头部左转不是负数，是 330~345**。

| 状态 | 判定区间 |
| ---- | ---- |
| 头右转 | `15 ≤ Z ≤ 30` |
| 头左转 | `330 ≤ Z ≤ 345` |
| 回正（死区） | `0~10` 与 `350~360` |

所以判定必须用**两组比较夹出区间**（`Greater + Less + And`），不能写成 `Z > 15` 这种单边判断 —— 单边判断在 0/360 环绕处会失效。左右各留 15° 宽的有效带、中间 ±10° 死区，这套调校值直接沿用即可。

### 2.3 角度映射位移

```
Split.Z → Remap(350~360 → 0~20)    左转时选中指示器的位移
Split.Z → Remap(0~10 → 0~-20)      右转时的位移
      → Combine.X → 位置
```

做的是「指示器跟着头转」的平滑反馈，`Clamp` 开启防止超范围。

## 五、改造清单

核心差异：示例是**从固定图片数组随机取**，我们要**动态生成算式和数字**。

| # | 改造项 | 从 | 到 |
| ---- | ---- | ---- | ---- |
| 1 | 题目内容 | `随机内容` 图片数组 + `Get Item from Array` | `Add`/`Subtract` 算结果，`Combine` 拼成 `56+22=?` |
| 2 | 选项内容 | 设置图片贴图 | 设置文字 `str` |
| 3 | 题数控制 | 图片数组长度 | `Index Generator` 计到 10 |
| 4 | 计分 | 无 | 答对累加，结算显示 `X/10` |
| 5 | 结算 | 无 | 复用 `Set Visibility`，隐藏答题组、显示总成绩 |
| 6 | 素材 | 32 张示例纹理（8 MB） | 删除，换文字组件 |

**建议顺序**：先在像塑里打开工程，确认能正常加载、摇头判定能跑通，再动出题逻辑。改造从第 1、2 项开始，那是玩法的核心。

## 六、干扰答案策略

只有一个干扰项，它的质量直接决定游戏好不好玩。纯随机的问题是：要么差得离谱一眼排除，要么全靠蒙。按**真实的口算错误类型**构造，让一部分题出现「两个答案看着都对」的犹豫感。

| 策略 | 权重 | 效果 | 例子 |
| ---- | ---- | ---- | ---- |
| 远差 | 40 | 差 6~22，一眼排除，给玩家喘息 | 78 → 95 |
| 进位错 | 20 | 差 ±10，**最常见的真实失误** | 78 → 68 |
| 个位错 | 15 | 十位对、个位错 | 78 → 73 |
| 极近 | 15 | 差 ±1~3，**必须真算一遍** | 78 → 77 |
| 位置颠倒 | 10 | 交换十位个位 | 78 → 87 |

这套权重实测（5 万次采样）的难度分布：差 1~3 占 22.9%、差 10 占 21.9% —— **约 45% 的题会让人犹豫**。

### 三条硬约束

| 约束 | 不满足会怎样 |
| ---- | ---- |
| **非负** | 减法题结果可能很小，减去偏移会出负数 |
| **不等于正确答案** | 两个按钮显示同一个数，玩家怎么选都算错 |
| **不超过 3 位** | 版面装不下 |

抽中策略后先校验，非法则逐级回退：原策略 → 远差 → 只加不减的保底值。

> 位置颠倒要取**交换最后两位**，不是整串颠倒 —— 125 整串颠倒成 521，首位差太远反而一眼排除；交换末两位得 152 才够迷惑。

## 七、避坑清单

- ❌ **别用单边比较判角度** —— 0/360 环绕会让 `Z > 15` 这类判断失效，必须用区间夹逼；
- ❌ **别删 `3D 跟踪头模`** —— 那是摇头角度的唯一数据源；
- ❌ **摇头阈值别设太小**，人脸微动会连续误答，10 题瞬间跑完；
- ❌ **示例纹理别留着上线**，32 张共 8 MB，会撑爆特效包 5 MB 限制；
- ❌ **不要导入外部背景音乐**，用平台内置免费音效，规避版权驳回；
- ⚠️ **干扰答案「差 1~3」是故意的**，别当成 bug 调掉；
- ✅ **减法必须大数减小数**，且干扰答案不能为负。
